# Ассистент по документам компании

Консольный AI-ассистент: отвечает на вопросы по папке документов (регламенты, FAQ, инструкции) и показывает, из какого файла взят ответ. Если ответа в документах нет, честно говорит об этом, а не выдумывает.

Учебный проект для портфолио. Компания «Лунный Кирпич» в демонстрационных документах вымышлена.

## Что умеет

- Читает файлы `.md` и `.txt` из папки и режет их на фрагменты (~800 символов, перекрытие 100, по границам абзацев).
- Находит самые подходящие фрагменты по вопросу (TF-IDF по символьным n-граммам, scikit-learn: устойчив к падежам и окончаниям).
- Просит Claude ответить только по найденным фрагментам и добавляет список источников: имя файла и номер фрагмента.
- Если в документах не нашлось достаточно близких фрагментов (лучший не дотянул до порога `MIN_SCORE`), отвечает «В документах нет информации по этому вопросу» и не обращается к API. Если порог пройден, но ответа во фрагментах нет, об этом говорит сама модель.
- Работает в двух режимах: один вопрос (`ask`) и диалог (`chat`).

## Как это работает

1. **Индексация.** Документы из `DOCS_DIR` нарезаются на фрагменты и индексируются TF-IDF.
2. **Поиск.** По вопросу выбираются `TOP_K` лучших фрагментов. Если лучший из них набрал меньше `MIN_SCORE`, ответ готов без обращения к API.
3. **Ответ.** В Claude уходят вопрос и фрагменты, близость которых не меньше `MIN_SCORE` и не меньше половины от лучшего, с системным промптом «отвечай только по фрагментам». Эти же фрагменты перечисляются в блоке «Источники» под ответом.

> **Какие данные уходят наружу.** При каждом вопросе, прошедшем порог, в API Anthropic отправляются сам вопрос и до `TOP_K` фрагментов документов (около 800 символов каждый). Не подключайте документы, которые нельзя передавать третьим лицам.

## Установка

Нужен Python 3.12 или новее (проект проверен на Python 3.14.5). Команды для PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

## Настройка .env

Скопируйте `.env.example` в `.env` и заполните значения:

```powershell
Copy-Item .env.example .env
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ANTHROPIC_API_KEY` | ключ API (обязателен) | нет |
| `CLAUDE_MODEL` | модель Claude | `claude-haiku-5-5` |
| `DOCS_DIR` | папка с документами (относительный путь считается от корня проекта) | `sample_docs` |
| `TOP_K` | сколько фрагментов передавать модели | `4` |
| `MIN_SCORE` | порог релевантности лучшего фрагмента, 0..1 | `0.10` |

Пустое значение означает «взять по умолчанию». `MIN_SCORE` должен быть от 0 до 1, `TOP_K` не меньше 1. Файл `.env` не попадает в git.

Ключ API создаётся в консоли Anthropic (console.anthropic.com). Запросы платные, стоимость зависит от модели и объёма переданных фрагментов, актуальные тарифы смотрите на сайте Anthropic.

## Примеры

Один вопрос:

```powershell
.venv\Scripts\python -m assistant ask "Сколько дней отпуска положено сотруднику?"
```

Пример вывода (иллюстративный: показывает формат, реальный вызов API при подготовке проекта не выполнялся, текст ответа модели будет отличаться):

```
Ежегодный оплачиваемый отпуск составляет 28 календарных дней. Сотрудникам со стажем более пяти лет добавляется ещё 3 дня.

Источники:
- vacation_policy.md, фрагмент 1
```

Вопрос не по теме:

```powershell
.venv\Scripts\python -m assistant ask "Какая погода на Марсе?"
# В документах нет информации по этому вопросу.
```

Диалог (выход по `exit`):

```powershell
.venv\Scripts\python -m assistant chat
```

Чтобы использовать свои документы, положите `.md` и `.txt` в любую папку и укажите её в `DOCS_DIR`.

## Структура

```
assistant/
  __main__.py   CLI (argparse): ask и chat
  config.py     настройки из .env
  loader.py     чтение и нарезка документов
  search.py     TF-IDF поиск
  llm.py        обращение к Claude API (таймаут, повторы, обработка ошибок)
  prompts.py    системный промпт и сборка запроса
sample_docs/    три вымышленных документа для демонстрации
tests/          тесты нарезки, поиска, промптов, обращения к API и CLI
```

## Ограничения

- Поиск лексический: находит фрагменты по совпадению кусков слов (n-граммы из 3-5 букв), а не по смыслу. Окончания и падежи не мешают («возврат» и «возвратом», «деньги» и «денег»), синонимы не распознаются. Служебные слова русского языка игнорируются. Если фрагментов 5 и больше, куски, которые встречаются более чем в 80% фрагментов, отбрасываются по статистике документов; на демо-документах таких кусков нет, и, например, название компании остаётся в словаре.
- Порог `MIN_SCORE` выбран так, чтобы вопросы по теме не отсекались: ложный пропуск стоит одного запроса к API, а модель сама ответит «в документах нет информации». Обратная сторона: часть посторонних вопросов порог проходит. Лексически близкие вопросы («Сколько стоит доставка пиццы?», «Как стать курьером?», «Как заказать такси?», «Сколько стоит iPhone?», «Как оформить кредит в банке?») доходят до модели, и отказ формулирует она. Вопросы без общих слов с документами («Какая погода на Марсе?», «Сколько калорий в банане?») обычно отсекаются без обращения к API, но из-за совпадения кусков слов проходят и некоторые из них (например, «Что такое квантовый компьютер?»). Проверено на 26 вопросах по теме и 11 не по теме в `tests/test_relevance.py`; подбор порога делался на части вопросов, остальные в нём не участвовали.
- При сбое сети запрос повторяется (до 2 повторов, таймаут 30 секунд на попытку), поэтому в худшем случае ответа или сообщения об ошибке придётся ждать около полутора минут.
- Без ключа ассистент не запускается, даже если вопрос был бы отсеян порогом без обращения к API. Порог `MIN_SCORE` подобран под демонстрационные документы и для других данных может потребовать настройки.
- Поддерживаются только `.md` и `.txt` в UTF-8; PDF и DOCX не читаются.
- Индекс строится при каждом запуске, история диалога между запусками не хранится.
- Нет веб-интерфейса, эмбеддингов и векторной базы.
- Ответ модели зависит от качества документов: ассистент не проверяет, актуальны ли они.
